# 合规与隐私说明（Compliance & Privacy）

本文档对应设计文档 [第 5 节「合规与隐私设计」](../../docs/superpowers/specs/2026-08-18-investment-board-design.md)
的逐条落实情况，并提供**使用者自查清单**。

> 核心原则：**代码级强制，而非靠自觉。**

## 设计第 5 节逐条落实说明

### 1. 只读边界（无交易能力）

- `backend/app/ths_client/` 只实现：扫码登录（`/qrcode`、`/poll`）、会话保活
  （`/session/check`）、自选查询（`/watchlist`）、持仓查询（`/positions`）。
  **不存在**任何下单 / 撤单 / 委托 / 成交方法。
- CI 静态检查 `scripts/check_no_trade.py` 用 **AST** 扫描 `backend/app/**/*.py`：
  - 任何以 `buy` / `sell` / `trade` / `order` / `place_order` / `easytrader` 为前缀的标识符
    （函数、方法、类、变量、属性、参数名，含 `buy_stock` 这类组合名）→ 拦截；
  - 任何非注释 / 非文档字符串行出现中文交易词「委托 / 下单 / 撤单 / 成交 / 买入 / 卖出」→ 拦截。
- AST 方式天然排除字符串字面量与注释，避免误报，同时不会漏报组合标识符。
  运行方式：`make check`，命中任一规则即非零退出。

### 2. 本地闭环

- 后端只绑定 `127.0.0.1`（`uvicorn --host 127.0.0.1`，默认端口 8210），仅本机可访问。
- 无遥测、无上报、无第三方统计 SDK；代码中不存在任何外部数据回传。
- CORS 只允许本机前端 `http://127.0.0.1:5173` / `http://localhost:5173`。

### 3. 凭据保险箱（Vault）

- 会话令牌经 **AES-256-GCM** 加密后写入 `~/.investment-board/session.enc`（`backend/app/vault/store.py`）。
- 加密密钥存系统 Keychain（macOS Keychain / Windows Credential Manager / Linux Secret Service，
  由 `keyring` 提供）；密钥**永不进代码、永不落盘明文**。
- 文件格式为 `v1 + nonce(12B) + ciphertext`，仅有密文；即使文件被拷贝也无法还原令牌。
- 会话过期由 `refresh_session()` 保活失败提示，前端要求重新扫码登录。

### 4. 一键清除

- 设置页「注销并清除全部本地数据」按钮 → `POST /api/logout` → `Vault.clear()`
  删除加密会话文件（`session.enc`）。
- 如需彻底清除密钥，另删系统 Keychain 中 `investment-board` 条目（见 README FAQ）。

### 5. 低打扰访问（限频与抖动）

| 数据源 | 频率 | 说明 |
| --- | --- | --- |
| 行情（新浪 / 腾讯） | ≥3s | `scheduler.quotes_interval=3.0` |
| 持仓 / 会话保活（THS） | ≥10s | `positions_interval=10.0`，THS 相关请求不高于此频率 |
| 新闻（东财 / 财联社） | ≥60s | `news_interval=60.0` |

- 所有循环在间隔上叠加 `random.uniform(0, 0.5)` 抖动，避免固定节奏被识别为抓取。
- 外部调用均设超时（默认 10s）与异常捕获；429 / 风控走日志告警 + 优雅降级。
- 请求头使用普通浏览器 UA，**绝不伪装他人、绝不绕过验证码**。

### 6. 透明合规声明

- `README.md`：项目简介、合规声明、隐私说明、常见问题（第三方接口失效如何降级、如何反馈）。
- `LICENSE`：MIT 协议 + 合规 / 免责附注（仅供个人学习研究、使用者自行确认对数据源的使用合规）。
- 前端看板 / 新闻 / 持仓界面均标注数据来源归属。

## 使用者自查清单（Checklist）

> 部署 / 使用前，建议逐项确认：

- [ ] 我已阅读 `README.md` 的合规声明，理解本项目**仅供个人学习研究、不构成投资建议**。
- [ ] 我已阅读 `LICENSE` 的合规附注，并自行确认对同花顺 / 新浪 / 腾讯 / 东财 / 财联社等
      数据源接口的使用符合其服务条款与当地法律。
- [ ] 我了解接入第三方账户查询接口可能违反其服务条款，**账号风险自担**。
- [ ] 我确认本项目为**只读**应用，不含任何交易功能；如需验证可运行 `make check`。
- [ ] 我知道程序会以受控频率（行情 3s / 持仓 10s / 新闻 60s）访问外部接口，不会高频抓取。
- [ ] 我知道我的会话令牌仅以加密形式保存在本机（Keychain + `~/.investment-board`），
      数据不会上传到除我主动登录 / 查询以外的任何第三方。
- [ ] 我了解第三方接口可能随时失效（如财联社电报接口返回 404 等），失效时界面会优雅降级，
      这不是本项目的 bug。
- [ ] 我不在受监管环境 / 生产环境把本项目的行情或新闻数据用于任何商业用途或对外分发。

## 合规静态检查的局限性

- `scripts/check_no_trade.py` 只扫描 `backend/app/**/*.py`，它保证**本项目源码**不含交易语义；
  它不审查第三方数据源，也不替代使用者对数据源条款的判断。
- 该检查是「代码级只读」承诺的静态防线：任何向 THS 客户端添加交易能力的改动都必须在
  CI 中被拦截，而不是依赖代码审查纪律。
